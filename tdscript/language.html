📑 Выбор редакции спецификации

Выберите версию спецификации для просмотра синтаксиса и контрактов подсистем:

Актуальная спецификация (TDscript Studio 1.1.0 / TDModules 1.4.0): Включает поддержку шестнадцатеричных литералов (0x76), индексации ByteArray[i], интерполяции переменных в LString, строгой диспетчеризации методов (TDS_E106), сторожа WATCHDOG и компактных диагностических строк для локальных LLM.

1. Базовый синтаксис и управление потоком

// Объявление неизменяемой (let) и изменяемой (var) переменной
let chipAddress = 0x76;
var status = false;

// Ветвление if / else
if (status == true) {
    print("Device is ready");
} else {
    print("Device offline");
}

// Цикл while со встроенным лимитом шагов (Step Limiter 10M)
var i = 0;
while (i < 5) {
    WATCHDOG.feed(); // Подпитка сторожа на каждой итерации
    i = i + 1;
}

2. Литералы и детерминированные типы данных

Тип данных Примеры литералов Особенности рантайма v1.4.0
Числа (Int / Long) 0x76, 0xD0, 0xF4, 100, 1000L Поддержка 16-ричных и 10-тичных чисел в лексере нативно.
Массивы байтов (ByteArray) Возвращаются методами I2C.read() Детерминированный вывод [0x60], индексация bytes[0] (0..255), метод bytes.size().
Локализация (LString) L"ALERT:Temp is {temp}C" Интерполяция {var} из активной области видимости. Конкатенация строк через + строго запрещена (ошибка TDS_E105) для сохранения грамматики 109 языков.
Строки (String) "sensor_01", "127.0.0.1" Обычные строки для хостов, IP-адресов и команд.
Булевы (Boolean) true, false Логические значения для флагов и условий.

3. Строгая диспетчеризация методов (TDS_E106)

В TDscript v1.4.0 вызов несуществующего метода у объекта (например, попытка вызвать метод Java safeI2CAddr.toString(16)) больше не возвращает тихо null. Рантайм выбрасывает явное исключение с точными координатами в коде: 

// Попытка вызвать неизвестный метод toString:
let safeAddr = 0x76;
let str = safeAddr.toString(16);

// РЕЗУЛЬТАТ В РАНТАЙМЕ:
// TDS_E106: E106@2:11 unknown_method=toString on=INT

4. Аппаратные модули хоста (Host SPI)

Модуль Метод и сигнатура Описание
I2C I2C.read(chip, reg, len) -> ByteArray Чтение len байт из регистра reg чипа chip (например, I2C.read(0x76, 0xD0, 1)).
I2C I2C.write(chip, reg, data) -> Boolean Запись байта или массива в регистр чипа (например, I2C.write(0x76, 0xF4, 0x27)).
PLC PLC.modbusRead(host, reg) -> Int Чтение Holding Register по протоколу Modbus TCP (например, PLC.modbusRead("127.0.0.1", 100)).
PLC PLC.modbusWrite(host, reg, val) -> Boolean Запись значения в регистр Modbus (например, PLC.modbusWrite("127.0.0.1", 101, 0)).
BLE BLE.connect(deviceId) -> Boolean
BLE.send(deviceId, cmd) -> String		 Подключение к Bluetooth LE периферии и отправка строковых команд с получением ответа.
NET NET.ping(host) -> Int ICMP-проверка доступности сетевого узла. Возвращает RTT в миллисекундах или -1.
WATCHDOG WATCHDOG.feed()
WATCHDOG.emergencyStop()		 Подпитка сторожевого таймера либо программный аварийный останов с отключением питания приводов.

5. Пространственная изоляция CapabilityScope и 16 флагов прав

Безопасность строится на двухуровневой модели: глобальный битовый массив прав (16 Capabilities) и гранулярный белый список физических координат CapabilityScope: 

// Пример проверки адресов хостом:
// Если CapabilityScope разрешает только I2C [0x76], обращение к 0x68 блокируется:
let res = I2C.read(0x68, 0x00, 1); 

// РЕЗУЛЬТАТ: Возвращает null и фиксирует в диагностике:
// SecurityException: SCOPE_VIOLATION: Address 0x68 not in I2C scope [0x76]
Классическая стабильная спецификация (TDscript v1.0.1 / Core 1.0): Используется в Android TUI лаунчере Tdroid, системных демонах и встроенных утилитах. Сохраняет 100% обратную совместимость с ранее написанными скриптами.

1. Особенности классического рантайма v1.0.1

  • Только десятичные числа: шестнадцатеричные литералы не поддерживаются лексером 1.0. Для обращения к чипу BME280 (0x76) следует указывать десятичный эквивалент 118, а для регистра (0xD0) — 208.
  • Символический LString: формат L"KEY" служил идентификатором для системного словаря ресурсов. Подстановка переменных через фигурные скобки {var} в версии 1.0.1 отсутствовала. Конкатенация строк через + также запрещена.
  • Байтовые массивы: метод print(bytes) в версии 1.0.1 выводил внутреннее представление JVM (например, [B@4f2a1b). Индексация bytes[0] требовала вспомогательных функций.
  • Мягкая диспетчеризация: вызовы неизвестных методов возвращали null без немедленного прерывания скрипта.
  • Диагностика: ошибки компиляции экспортировались в подробный многострочный JSON CompilerErrorDiagnostic.

2. Пример скрипта для TDscript v1.0.1

// Чтение датчика в стиле TDscript 1.0.1 (десятичные адреса 118 и 208)
let chip = 118; // 0x76
let reg = 208;  // 0xD0
let data = I2C.read(chip, reg, 1);

if (data != null) {
    print("CHIP_ID_READ_SUCCESS");
} else {
    print("READ_FAILED");
}

3. Рекомендации по совместимости

Если ваш скрипт предназначен для запуска внутри мобильного лаунчера Tdroid, используйте десятичные литералы и базовый синтаксис v1.0.1. При переносе скриптов в среду TDscript Studio рекомендуется перейти на более наглядный синтаксис v1.4.0 с hex-литералами и интерполяцией LString.

📑 Language Specification Selection

Modern Specification (v1.4.0 / Core 1.1): Hexadecimal literals (0x76), ByteArray[i] indexing, LString variable interpolation, strict method dispatch (TDS_E106), WATCHDOG subsystem, and GBNF grammar. 
let chip = 0x76;
let reg = 0xD0;
let bytes = I2C.read(chip, reg, 1);
let id = bytes[0];
let alert = L"TEMP_ALERT:Chip {chip} identified with ID {id}";
print(alert);
Legacy Specification (v1.0.1 / Core 1.0): Active in the Tdroid launcher and background services. Relies on decimal address literals (e.g. 118 for 0x76), symbolic LString, and standard JSON diagnostics. 
let chip = 118; // 0x76 in decimal
let reg = 208;  // 0xD0 in decimal
let data = I2C.read(chip, reg, 1);
print("BME280 Read");
