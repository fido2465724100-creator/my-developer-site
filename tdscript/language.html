📑 Выбор редакции спецификации

Выберите версию спецификации для просмотра синтаксиса и контрактов подсистем:

Основная спецификация (TDscript Studio 1.1.0 / TDModules 1.5.0, Спецификация Core 1.1): Включает поддержку шестнадцатеричных литералов (0x76), тернарного условного оператора (? :), составных присваиваний (+=, -=, *=, /=, %=), авто-декларации в language: ai;, операторов прерывания циклов (break / continue), директивы language: ai; для LLM-агентов, человеческих ключевых слов без сокращений (переменная, печать), индексации ByteArray[i], интерполяции переменных в LString, строгой диспетчеризации методов (TDS_E106) и сторожа WATCHDOG.
🔤 Лексический справочник (110 языков) 📐 Скачать / Просмотреть эталонную GBNF-грамматику (grammar.gbnf)

1. Базовый синтаксис и управление потоком (v1.5.0)

// Объявление языка: language: ru; (человеческий) или language: ai; (для ИИ-агентов)
language: ru;

// Объявление неизменяемой (пусть / let) и изменяемой (переменная / var) переменной
пусть адресЧипа = 0x76;
переменная готовность = false;

// Тернарный условный оператор (? :)
переменная статус = (готовность == истина) ? "ГОТОВ" : "ОЖИДАНИЕ";

// Ветвление если / иначе (if / else)
если (готовность == истина) {
    печать("Устройство готово к обмену");
} иначе {
    печать("Ожидание инициализации...");
}

// Цикл пока (while) с выходом по break и составным присваиванием (+=)
переменная попытка = 0;
пока (попытка < 10) {
    попытка += 1; // Компактное инкрементирование
    let data = I2C.read(адресЧипа, 0xD0, 1);
    если (data != пусто) {
        печать("Датчик ответил на попытке: ", попытка);
        прервать; // Выход из цикла без лишних флаговых переменных
    }
    WATCHDOG.feed(); // Подпитка сторожа
}

2. Операторы и выражения (v1.5.0)

Группа операторов Синтаксис и символы Поведение и оптимизация
Присваивание =, :=, +=, -=, *=, /=, %= Поддержка составных присваиваний мутирует переменные без дублирования идентификатора (экономия до 3 токенов на шаг). В режиме language: ai; поддерживается авто-декларация без let/var.
Тернарное ветвление условие ? выражение1 : выражение2 Вычисляет и возвращает значение одной из ветвей по результату булевого условия. Экономит до 53% токенов по сравнению с конструкцией if-else.
Арифметика +, -, *, /, % Целочисленные и вещественные операции с автоматическим приведением типов.
Сравнение ==, !=, <, <=, >, >= Строгое сравнение скаляров и байтов.
Логика &&, ||, ! Логические операции И, ИЛИ, НЕ с коротким циклом вычисления. Допускаются синонимы and/or, и/или.

Булевы (Boolean) true, false Логические значения для флагов и условий.

4. Строгая диспетчеризация методов (TDS_E106)

В TDscript v1.5.0 вызов несуществующего метода у объекта (например, попытка вызвать метод Java safeI2CAddr.toString(16)) больше не возвращает тихо null. Рантайм выбрасывает явное исключение с точными координатами в коде: 

// Попытка вызвать неизвестный метод toString:
let safeAddr = 0x76;
let str = safeAddr.toString(16);

// РЕЗУЛЬТАТ В РАНТАЙМЕ:
// TDS_E106: E106@2:11 unknown_method=toString on=INT

5. Аппаратные модули хоста (Host SPI)

Модуль Метод и сигнатура Описание
I2C I2C.read(chip, reg, len) -> ByteArray Чтение len байт из регистра reg чипа chip (например, I2C.read(0x76, 0xD0, 1)).
I2C I2C.write(chip, reg, data) -> Boolean Запись байта или массива в регистр чипа (например, I2C.write(0x76, 0xF4, 0x27)).
PLC PLC.modbusRead(host, reg) -> Int Чтение Holding Register по протоколу Modbus TCP (например, PLC.modbusRead("127.0.0.1", 100)).
PLC PLC.modbusWrite(host, reg, val) -> Boolean Запись значения в регистр Modbus (например, PLC.modbusWrite("127.0.0.1", 101, 0)).
BLE / BT BLE.connect(deviceId) -> Boolean
BLE.send(deviceId, cmd) -> Boolean
BLE.readLine() -> String		 Подключение к Bluetooth LE периферии и обмен строковыми данными (объекты BLE и BT являются взаимозаменяемыми алиасами).
NET NET.ping(host) -> Int ICMP-проверка доступности сетевого узла. Возвращает RTT в миллисекундах или -1.
WATCHDOG WATCHDOG.feed()
WATCHDOG.emergencyStop()		 Подпитка сторожевого таймера либо программный аварийный останов с отключением питания приводов.

5. Пространственная изоляция CapabilityScope и 16 флагов прав

Безопасность строится на двухуровневой модели: глобальный битовый массив прав (16 Capabilities) и гранулярный белый список физических координат CapabilityScope: 

// Пример проверки адресов хостом:
// Если CapabilityScope разрешает только I2C [0x76], обращение к 0x68 блокируется:
let res = I2C.read(0x68, 0x00, 1); 

// РЕЗУЛЬТАТ: Возвращает null и фиксирует в диагностике:
// SecurityException: SCOPE_VIOLATION: Address 0x68 not in I2C scope [0x76]
Классическая стабильная спецификация (TDscript v1.0.1 / Core 1.0): Используется в Android TUI лаунчере Tdroid, системных демонах и встроенных утилитах. Сохраняет 100% обратную совместимость с ранее написанными скриптами.

1. Особенности классического рантайма v1.0.1

  • Только десятичные числа: шестнадцатеричные литералы не поддерживаются лексером 1.0. Для обращения к чипу BME280 (0x76) следует указывать десятичный эквивалент 118, а для регистра (0xD0) — 208.
  • Символический LString: формат L"KEY" служил идентификатором для системного словаря ресурсов. Подстановка переменных через фигурные скобки {var} в версии 1.0.1 отсутствовала. Конкатенация строк через + также запрещена.
  • Байтовые массивы: метод print(bytes) в версии 1.0.1 выводил внутреннее представление JVM (например, [B@4f2a1b). Индексация bytes[0] требовала вспомогательных функций.
  • Мягкая диспетчеризация: вызовы неизвестных методов возвращали null без немедленного прерывания скрипта.
  • Диагностика: ошибки компиляции экспортировались в подробный многострочный JSON CompilerErrorDiagnostic.

2. Пример скрипта для TDscript v1.0.1

// Чтение датчика в стиле TDscript 1.0.1 (десятичные адреса 118 и 208)
let chip = 118; // 0x76
let reg = 208;  // 0xD0
let data = I2C.read(chip, reg, 1);

if (data != null) {
    print("CHIP_ID_READ_SUCCESS");
} else {
    print("READ_FAILED");
}

3. Рекомендации по совместимости

Если ваш скрипт предназначен для запуска внутри мобильного лаунчера Tdroid, используйте десятичные литералы и базовый синтаксис v1.0.1. При переносе скриптов в среду TDscript Studio рекомендуется перейти на более наглядный синтаксис v1.5.0 с hex-литералами и интерполяцией LString.

📑 Language Specification Selection

Modern Production Specification (v1.5.0 / Core 1.1): Includes hex literals (0x76), ternary operator (? :), compound assignments (+=, -=, *=, /=, %=), implicit variable declaration in language: ai;, loop control (break / continue), language: ai; & language: <code>; directives, full 110-language vocabulary without abbreviations (let, var, while, print), BLE runtime alias, ByteArray[i] indexing, and WATCHDOG timer.

language: ai;

chip = 0x76;
reg = 0xD0;
bytes = I2C.read(chip, reg, 1);
id = bytes != null ? bytes[0] : 0;
status = id == 0x60 ? "BME280_OK" : "UNKNOWN_DEVICE";
