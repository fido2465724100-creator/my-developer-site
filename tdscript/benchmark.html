🎯 Цель исследования: Поиск идеального языка для ИИ-агентов

В последнее время большие языковые модели (LLM) активно внедряются в промышленную автоматизацию, управление робототехникой, микроконтроллерами и системами "умного дома". Однако подавляющее большинство инженеров продолжает использовать классические языки: Python, C/C++, JavaScript, Lua и Kotlin.

Главный вопрос бенчмарка: Подходят ли языки, созданные для людей 30–50 лет назад, для работы современных локальных ИИ-агентов в условиях ограниченных ресурсов?

Человеческие языки vs Машинная генерация

Языки для людей полны синтаксического сахара, неявных преобразований типов и миллионов внешних библиотек. Для компактных локальных моделей (3B–9B параметров) это порождает галлюцинации импортов, ошибки сборки и многословный шаблонный код (boilerplate).

Цена ошибки в физическом мире

В веб-разработке ошибка скрипта — это лишь запись в лог. В автоматизации физического оборудования неверный адрес I2C (например, 0x68 вместо 0x76) или зависший цикл без сброса Watchdog может физически сжечь микросхему или перегреть промышленный котёл.

Чтобы выяснить это экспериментально, мы разработали автономный стенд тестирования и сравнили 7 языковых профилей в абсолютно равных условиях на 10 реальных инженерных задачах управления периферийными шинами (I2C, Modbus TCP, BLE, Watchdog, ICMP Ping).

⚙️ Методология тестирования и автономный цикл (Agentic Loop)

Бенчмарк моделирует реальную работу автономного ИИ-ассистента инженера в среде TDscript Studio по схеме замкнутого цикла с обратной связью:

[1. Запрос инженера] ➔ Описание задачи на естественном языке
    ⬇
[2. Аппаратный снимок (Probe)] ➔ В промпт подмешиваются доступные адреса железа
    ⬇
[3. Генерация кода LLM] ➔ Модель генерирует скрипт в рамках токен-бюджета (1000 токенов)
    ⬇
[4. Исполнение в песочнице] ➔ Компиляция/запуск в изолированной среде с эмуляцией шин
    ⬇
[5А. Успех (PASS)] ➔ Код выполнил задачу, проверен вывод (stdout/регистры)
    ИЛИ
[5Б. Ошибка (FAIL)] ➔ Захват диагностического отчёта (Синтаксис / Scope / Вывод)
    ⬇
[6. Авторемонт (Self-Repair)] ➔ Отправка ошибки модели обратно (до 3 попыток суммарно)

Условия аппаратного стенда:

  • GPU: NVIDIA GeForce GTX 1070 (8 ГБ VRAM, архитектура Pascal, CUDA 12.x).
  • Инференс-движок: llama-server (ветка llama.cpp) с полным аппаратным offload слоёв.
  • Автономность: Полная локальность, нулевой доступ к облакам, интернету или внешним сервисам.
  • Лимит контекста: 4096 токенов контекст, 1000 токенов максимальный вывод на один ответ.
  • Языковые рантаймы в тестах:
    1. TDscript Base (v1.4.0): стандартный рантайм TDscript с подробными JSON-ошибками.
    2. TDscript Experimental (AI-First): оптимизированный под ИИ синтаксис со сжатым протоколом авторемонта.
    3. Python 3.12: с изолированным субпроцессом и эмуляторами шин.
    4. C++ (Arduino/ESP32 style): компиляция через g++ с эмуляцией регистров Wire и Serial.
    5. Lua 5.4: легковесный встроенный скриптинг.
    6. JavaScript (Node.js 20): асинхронный V8 рантайм.
    7. Kotlin 2.0: компиляция через kotlinc и выполнение в JVM.

💡 Глубокий анализ: Почему языки ведут себя по-разному в руках ИИ?

1. Феномен исчерпания токенов рассуждений (Thinking Bottleneck)

В Тесте №4 на модели 4B Unloop 89.2% всех сбоев (157 из 176) во всех языках вызваны исчерпанием лимита 1000 токенов (TRUNCATED_IN_THINKING). Современные рассуждающие модели тратят до 800–950 токенов на внутренний монолог. Языки с громоздким синтаксисом (C++, Kotlin) не оставляют токенов для вывода самого кода.

2. Рекордная лаконичность TDscript (3.5 – 5.6 строк)

TDscript генерирует в 2–3 раза меньше кода, чем Python (8.5–9.7 строк) и C++ (11–15 строк). Чем меньше строк генерирует модель, тем быстрее она успевает выдать рабочий код до исчерпания контекстного окна.

3. Экономика токенов: TDscript Experimental на 45% дешевле

Благодаря протоколу сжатой диагностики E104@line:col exp=0x76 got=0x68 стоимость успешного решения задачи снизилась с 4149.9 токенов (в Base) до 2275.2 токенов (в Experimental), а число итераций ремонта упало до ровно 1.00.

4. Нулевые синтаксические ошибки с GBNF-грамматикой

В то время как C++ и Kotlin постоянно генерировали ошибки компиляции (пропущенные скобки, неверные сигнатуры), TDscript при генерации с GBNF-грамматикой показал 0% синтаксических ошибок.

👉 Итоговый вывод: Специализированный язык TDscript AI-First доказал своё превосходство по компактности, безопасности и экономии токенов, являясь идеальной средой для автономных встраиваемых агентов на базе локальных LLM.

💻 Как воспроизвести бенчмарк самостоятельно

Весь код бенчмарка и тестов открыт в модуле :benchmark репозитория TDscript Studio:

# 1. Запуск llama-server с моделью Qwen 3.5:
./llama-server -m /path/to/Qwen3.5-9B-Instruct.gguf --port 8765 -ngl 36 -c 4096

# 2. Запуск живого прогона всех 70 тестов:
cd TDscript-Studio
./gradlew :benchmark:run --args="--url=http://127.0.0.1:8765/v1 --tasks=all --profiles=all --out=BENCHMARK_REPORT.md"

# 3. Запуск изолированных юнит-тестов (Dry-Run без видеокарты):
./gradlew :benchmark:test
